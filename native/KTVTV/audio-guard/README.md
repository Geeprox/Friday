# Friday KTV audio companion

Package `local.friday.ktv.audio` is a separate UID, signed with the production KTV certificate. Its only exported components are signature-protected `GuardService` and `PermissionActivity`. It has no network permission, HTTP endpoint, boot receiver, launcher entry, household configuration or raw-audio store. The permission activity requests this package's own RECORD_AUDIO permission and returns without starting audio.

The core is migrated from frozen GlobalMic carrier 0.4. It keeps independent foreground ownership, Binder-death cleanup, a persistent unresolved-lease marker, the carrier-readiness gate, and final STOP/disable after a late START. The first supported target remains the verified UGREEN format/vendor product; card, device and Android input IDs come only from current unique USB device/capability/address and vendor-query evidence. No card/input ID is hardcoded. Other microphone models are not implicitly qualified.

The ordinary 48 kHz stereo PCM16 MEDIA/NONE zero carrier remains active for the entire native lease. START requires PLAYING, the expected actual built-in speaker route and playback-head growth. No automatic test/session deadline is added. Numeric calls, setpoints and carrier progress are diagnostics, not physical latency or gain readback.

`setEnabled(false, gain)` on an owned lease requests MIC_ZERO then SYSTEM_ZERO. Native capture and the carrier remain owned, without saving audio. A positive gain restores MIC_GAIN then SYSTEM_GAIN_100. From companion 0.2, gain accepts every integer 0–100, matching the actual vendor clamp and the phone slider. Zero remains mute. Main 0.55 requires the matching signed companion 0.2 or newer; an older six-step companion is unavailable until the pair is updated. Latest gain-request sequencing rejects queued stale nonzero writes after mute or hard stop. Initial enable requests min(5, desired gain) first, then the current desired gain; it never requests a bootstrap gain above a low user setting. The OEM START itself still has the documented non-atomic unity window before zero setters return. Only explicit stop, background, route change, owner death or service termination performs numeric STOP, disable and carrier release. An already in-flight vendor call is not atomically cancellable; its subsequent latest request/STOP cleanup remains required.

`VendorMicClient` API:

- `VendorMicClient(Activity, Listener)` where `Listener.onChanged(JSONObject)` is posted asynchronously on the UI thread.
- `available(Context)`, `permissionReady()`, explicit `openPermission()`; none starts microphone audio or opens a prompt automatically.
- `setForeground(boolean)`, `setEnabled(boolean,int)`, `stop()`, `close()`.
- `state()` returns normalized status, desired/desired_enabled, desired_gain, enabled, permission_ready, native_capture_owned, mic_muted, stopping, stop_verified, last_error and nested guard state. `readback()`/`telemetry()` return the raw guard snapshot.
- `normalizeGain(int)` chooses the nearest supported nonzero step, choosing the lower step on ties; initial/default desired gain is 20.

`setForeground(false)`, stop and close cancel the client's pending desire. Guard-detected route/error stops also clear it; integration must not blindly reapply an old room command every tick. `close()` keeps its bound cleanup observation until STOP/status 2/disable and carrier release are reported; the independent Binder death path remains if the main process is killed first. A service crash requires cleanup and a fresh enable request. Client callbacks never start permission UI.

Build only `src/**/*.java` against android.jar; no native library or external dependency is needed. Pure protocol/race tests are in `tests`. `ZeroCarrierCancelBeforeStartTest` also compiles `ZeroOutputCarrier.java` against android.jar, then executes only its unopened cleanup path. `VendorMicDesiredStateTest` compiles the production `VendorMicClient.java` against android.jar and exercises only its pure nested DesiredState; no Context, Handler or audio instance is created.

Production integration must keep AudioEngine input null in an immutable output-only mode. UI microphone state is independent from the software PcmMixer mute/safety fields. From companion 0.3 / main 0.56, all positive gain is gated by a fresh, lease-bound protection observer heartbeat. Command 8 accepts only bounded scalar monitor identity/progress, stage, frequency and wet budget; command 9 is a fresh explicit reset. No free-form vendor parameter crosses IPC. A closed numeric post-EQ payload applies up to eight non-boosting notches through the verified 61699 stereo post-EQ path. Gain caps and mute latch survive ordinary gain edits/polls. Missing progress for 750 ms latches zero; if zero cannot complete within a further 500 ms, the independent STOP dispatcher is used. Same-target pending gains coalesce so heartbeat traffic cannot starve the setter ACK.

The desired user gain and completed effective setpoint are separate. Dry voice reserves headroom for the bounded wet return before the latter can activate; the two application return buffers must advance after its applied zero epoch before dry headroom is restored. These are digital/setpoint guarantees, not acoustic gain or hardware-delay measurements. Native gain/flag/EQ getters remain unavailable. GlobalMic fresh START still has its documented unity interval before zero setters complete; long incomplete START has a separate 750 ms STOP cutoff. No live execution or acoustic safety claim follows from this offline implementation.
