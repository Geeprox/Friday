# 开发与验证

可选 ARL/API 通道的数据流和用量语义见[智能通道](intelligence.md)。新增回归使用合成
HTTP/WebSocket 与 PNG，正常测试不需要真实 API Key。`tests/test_intelligence_*` 覆盖
并发预留、跨日、降级、设置和主动语音生命周期；`tests/test_ktv_background.py` 覆盖歌曲
媒体票据与可选图片故障。纯 Java 状态测试需显式 `FRIDAY_TEST_JAVA_HOME`，缺少时跳过，
不会触发系统 Java 安装器。浏览器检查使用独立示例服务，不能据此宣称真实付费调用或电视验收。

先阅读 [AGENTS.md](../AGENTS.md)，核对当前任务的实现、验证与授权范围。公共约定在[元仓库开发规范](https://github.com/lijunfeng722/friday-project-index/blob/main/docs/development.md)统一维护，本仓库保留部署、隐私、设备发现与公开历史要求。

## 开发环境

使用锁定依赖和合成测试数据。回归环境使用 Python 3.12，包括固定的抽象语法树（AST）契约检查。创建环境：

```sh
uv sync --locked --python 3.12 --group dev --extra airplay --extra nas-connection --extra privacy-playback --extra ktv
```

完整测试套件运行前，使用 `npm --prefix workers/geek ci --ignore-scripts` 安装可选 Geek 工作进程的测试依赖；完整回归的依赖参数以 [CI 工作流](../.github/workflows/ci.yml)为准。基础控制台安装仍支持 Python 3.11 及以上版本。

完整回归包含 KTV 的真实 PNG 二维码生成，因此须选择已锁定的 `ktv` extra；
`qrcode` 本身不包含 `PyPNGImage` 所需的 PyPNG。无需为运行测试启动 KTV、登录、扬声器或电视。

体感游戏的 Node 回归通过 `FRIDAY_TEST_PYTHON` 显式选择同一锁定测试环境的 Python；没有设置时才兼容本地 `.venv/bin/python`。独立源码导出与 CI 应设置该变量，不必在导出目录复制环境或建立兼容软链。这只调整测试入口，不改变用户操作或产品画面。

照片处理的 Pillow 与 HEIF 解码器由主依赖锁定；[照片处理说明](PHOTO-EDITING.md)
记录真实编解码、子进程预算和取消责任。依赖解析使用 `uv lock`，不以精确同步已有
运行环境代替锁文件更新；当前安装版和旧环境继续单独保留。

## ARL 客户端与完整宿主测试

按[桌面构建说明](FRIDAY-DESKTOP-BUILD.md)显式准备固定公开 SDK 后，可在新测试进程中
使用 `PYTHONPATH=<该输入目录>` 和 `FRIDAY_TEST_ARL_SDK_INPUT=<该输入目录>` 运行客户端
及消费者回归。SDK 只参与合成协议与回执验证；CI 也使用同一固定清单，不要求开发者私有目录。
常规 Python 导入也必须设置 `PYTHONDONTWRITEBYTECODE=1`，避免在固定输入中生成
`__pycache__`；额外文件仍会使来源核验和清理拒绝，不能用忽略缓存的方式放宽清单。

CI 通过 `scripts/run_ci_regression.py` 为每个回归进程创建独占的 `/tmp/fci-*`，同时将它设为
`TMPDIR`，并把 pytest `--basetemp` 放在其 `p/` 子目录。这样 SQLite 仍遵守原本的
本机临时位置校验，Unix socket 也保留短路径余量；回归期间持有锁，结束后核对来源、
Git、类型和打开句柄再回收，保留外部小型 JSON 回执。引用不明时保留现场并使 job 失败。
默认 cacheprovider 保持启用，`cache_dir` 显式设为同一独占根的 `pytest-cache/` 并随之回收。
`RUNNER_TEMP` 只保留 SDK 输入和准备回执，不直接用作 pytest 数据库目录。
本机开发仍遵守项目缓存命名空间；设置 `TMPDIR` 时须指向本任务已创建的隔离目录，
需要短 socket 的测试才使用有来源记录、可回收的 `/tmp` 例外。
该例外使用两平台都有的 `/tmp`；macOS 将其解析到 `/private/tmp`，不把该 macOS 路径写死在 Linux 测试中。

打包门禁测试的稀疏合成 App 和校验回执放在正式认可的项目缓存中，以独占锁、清单及
清理回读管理；测试数据的位置不能绕过正式 App 根目录、SDK 来源或副作用检查。

`tests/test_arl_priority_consumer.py` 覆盖真实公开 SDK 的 v2 协商、首次优先级提交、回执、
上下文撤销、取消与不重放。完整宿主的身份生产器、资源租约及代次替换由原有四个集成用例
单独覆盖；它们需要显式的 `FRIDAY_TEST_ARL_PRIORITY_HOST_SOURCE`，不能把公开客户端
缺少 `friday_profile` 或 `priority_host` 当作应扩充冻结 SDK 的理由。

完整宿主集成须在全新进程中把所选、已审阅的完整 SDK 根目录置于 `PYTHONPATH`，然后
设置上述变量运行 `tests/test_homeplane_arl_planning_priority.py`。未提供时明确跳过该
宿主范围；显式输入缺接口或与已导入 SDK 不同则失败，禁止替换已导入命名空间。
原生 sealed actor 用例也要求该明确来源及其候选；源 seal、身份和授权断言继续保留。
普通 CI 不提供私有宿主组合，不能将其跳过写成宿主或真实模型验收。

默认 API 测试分别注入无外部传输的会话或调用方持有的运行时，仍检查创建/启动/关闭
次数及 API、HA 订阅原有行为。线程异常视为错误，不吞掉 socket 越界尝试来消除警告。
桌面诊断日志回归也显式注入合成会话，保留网络拒绝、日志内容及服务生命周期断言。
这些是开发与验证入口变化，无终端用户功能、使用步骤或产品截图变化。

## 验证与隐私

### 四路摄像头同机对照

使用包含本功能的安装版，等四台已接入摄像头都在取流且预览新鲜。采用同一房间活动和设备配置，先保持大部分画面静止观察降频，再以相同顺序在两段各一次叫唤醒词。脚本不会启动或打开摄像头。主镜头需事先在摄像头详情由使用者启用「跟随人物」，实际转向和对准需现场观察。

```sh
python3 -B scripts/embodied/compare_vision.py --seconds 24 --compare
```

省略 `--compare` 只读取降频状态。默认使用本机桌面版目录和 8740 端口，隔离环境可指定 `--data` 和 `--console-port`。先确认没有其他高负载任务改变主机条件。比较两段每台镜头的推理提交、静帧跳过、识别帧，以及主机 CPU 和内存。每段前两次系统资源读取用于建立本段基线，后续使用不同读数的采样计算汇总。`host_cpu_samples` 给出实际纳入的 CPU 样本数。

`preview_frames` 是预览入口接收的新 JPEG 帧数，`preview_fresh_samples` 是采样时仍有新鲜预览的次数。`recognition_samples` 给出识别正常、等待与恢复中的次数。`preview_fresh_without_recognition_samples` 单列预览正常但识别停滞的次数。采集会话保持时，预览短时过期或整段未完成识别仍写入结果。`sampled_frame_age_p95_ms` 仅使用识别正常样本中最近完成帧的管线耗时，缺少这类采样时为 `null`。

`body_rescue_passes` 是收到原生识别回执的裁切补检次数。同一帧可能执行两次。与每路 `inference_submitted` 一起对照，区分少提交整帧与少做空场裁切的开销。旧版原生识别器无该计数时显示为 `null`。

每路的 `timings` 使用本段开始和结束的累计计数差，列出样本数、p95 所在档位上限和超出量程的样本数。空样本和落在最高档之外的 p95 显示为 `null`。旧版 worker 没有时延计数时，`timings` 为空。

| 字段 | 起止点 |
| --- | --- |
| `vision_request` | Python 开始原生识别请求，到管道返回或请求结束。含序列化与管道等待，失败也计入 |
| `native_processing` | 原生识别返回的单帧处理时间 |
| `asr_request` | 调用转写进程，到收到结果或请求结束。失败也计入 |
| `voice_segment_to_wake_confirm` | 有效语音段就绪，到确认明确唤醒词。包括收音仲裁与转写等待 |
| `wake_confirm_to_motor_submit` | 确认唤醒词，到向采集进程提交相关云台命令 |
| `motor_submit_to_ack` | 云台命令提交，到接收成功回执 |

报告按收音镜头区分收到的音频包、达到语音分段门槛、转写发起、收到转写结果、确认唤醒、云台提交和成功回执。旧版 worker 缺少的计数显示为 `null`。实体转动与对准由现场观察确认。镜头关闭、采集进程退出或重连、识别会话或镜头模式变化、计数回退、游戏或手势体验占用时结束对照。

检查本机诊断中的 `voice_audio_backlog` 和 `voice_audio_stale`，分别定位语音包积压和过期。四路接收隔离测试使用合成片段和阻塞的语音活动检测，核对各路画面、声音复核输入和云台回执能否继续到达，以及已撤销的检测结果能否被废弃。实机语音和 CPU 延迟需单独测量。

私有运行日志通过同一个唤醒编号关联转写确认、派发和回执。`wake_motor_privacy_timeout` 表示发送时限内没有等到隐私读回，`wake_motor_dispatch_expired` 表示派发前期限已过，`wake_motor_observation_changed` 表示当前画面或目标已使原决定失效。这些状态均未发送云台命令。`wake_motor_rejected` 表示已提交但采集进程或设备明确拒绝。日志只保留固定状态码。

首页状态的生命周期回归覆盖后台创建、首次读取、过期、返回前台、手动刷新及退出取消；后台定时轮询仍暂停。此修复恢复既有首页的状态显示，不新增用户操作步骤；当前渲染证据与真实家庭验收分别记录。

常规测试不创建真实家庭会话，也不运行真实模型或硬件。使用隔离临时目录，生成证据放在 `.artifacts/`，公开前分别检查源码工作区和独立导出的源码副本。

聚类挂起回归先等待合成子进程完成冷导入，再交给原有识别进程管理器运行；包含超过工作预算的
启动延迟样例，避免导入时间耗尽预算而误测其他分支。工作时限、停止与回收预算及未确认退出断言保持不变。

KTV 的 HTTP 协议夹具关闭后台健康刷新，完整就绪断言前须用原有文件和数据库探针更新证据；
同时验证过期证据被拒绝。保留生产健康有效期及全部就绪闸门，慢测试不能靠放宽门槛通过。
手机状态读取在同一个 SQLite 快照内查询协调会话，避免与电视心跳的提交互相等待。
隔离回归使电视心跳在手机持有读事务时进入提交，并校验两边都能完成。用户操作和界面无需调整。
手机回到前台时独立请求房间快照。遇到短时连接故障，快照在常规长轮询以外退避重试，
恢复后回到常规校准间隔。隔离回归覆盖长轮询挂起时的重试和页面隐藏时的取消。

ARL 迟到回执测试用事件明确扣住提交和取消返回，分别触发 deadline 与调用方取消，
验证 busy 锁及无积压后再等待真实工作线程退出，不用固定休眠猜测线程调度。

运行事件使用固定、有界的事件码，不记录凭据、原始转写、媒体、原始名称或异常正文。隐私测试应验证实际数据边界，不能只检查界面提示文字。

## 跨仓库交付

新增人工提交、解释性注释和协作规范正文使用中文，保留必要的文件名、命令与技术术语。运行 `python3 scripts/check_dev_policy.py check` 检查当前约定；有明确任务基线时用 `--base` 核对新提交，保留旧历史和上游信息。

新增用户可见能力或操作变化时同步用户手册的步骤、限制和 FAQ；架构、接口、授权或部署变化时更新对应技术说明和必要 Mermaid 图。涉及依赖安装器时同步用户手册的下载副本与 SHA256 清单，涉及跨仓库维护入口时更新元仓库。纯内部变更说明无用户文档影响及理由。

PR 模板记录三类文档影响，检查工作流验证固定版本的规则和新增人工提交；注释质量、文档覆盖与真实设备效果仍由审查和对应实测确认。

同机对照视觉推理使用独立的短时诊断覆盖。镜头进程的 loopback 内部接口核对本机控制凭据，在同一采集会话按时限临时保持满频。计时结束后恢复按活动采样。报告使用分路计数、耗时分布、画面年龄和系统负载。短时对照在已授权的同一台 Mac 与同一组摄像头上进行。
