# 选择智能通道与管理用量

在 **设置 → 智能服务 → 智能通道与每日用量** 选择文字处理方式：

- **ARL · Codex**：保持现有共享运行服务，使用该服务自己的账户与用量。
- **OpenAI API**：直接使用自己的 API 项目；勾选“允许云端文字处理”后生效。
- **自动 · API 优先**：优先尝试 API，按“API 不可用时改用 ARL”的选择回退。
- **仅本地功能**：不发起云端增强调用，已保存规则、设备按钮、点歌与播放照常工作。

API 与 ARL 使用不同账户来源。已经在其他应用或 Codex 中连接 OpenAI，不代表 Friday
已经取得该 Key。可在本机“配置已有 API Key”中保存已有 Key，或给 Friday 服务设置
`OPENAI_API_KEY`。页面只显示是否配置，不回显 Key，也不把“保存成功”当作余额核验。
默认不创建新 Key、不打开云推理、麦克风或自动背景生成。

文字解释使用本次问题和必要的设备目录标签、能力及参数范围；旧版即时规划还包含
目标引用、开关状态和亮度、温度等有限属性。家庭状态问答的读数由本地查询产生，
不依靠模型猜测。API 不接收任意 HA 属性、登录文件、家庭画面或原始本地语音。

## 每日上限与降级

可分别设置 API 请求次数、文本 Token、图片张数和语音会话秒数，0 表示暂停对应调用。
模型、单次文字输出上限、背景保留张数与重置时区也可自行配置。文字 Token 不包含
图片与实时音频的计费 Token；后两者由独立张数和会话时间限制控制。这里是 Friday
自己的用量闸门，不是账户美元余额或所有应用共用的账单上限。

调用前原子预留预算；并发与重启共用本机账本。完成后用可靠回执结算，超时、取消
或没有可靠用量的结果保留预留，同一次调用不自动重发。背景预取失败后退避最多 15 分钟，
之后仍需通过预算才可再试；更改设置后会重新评估。已明确被 API 拒绝的请求不记文本
Token，仍计一次请求尝试。修改时区不会立刻清空本周期用量；下一重置点之后采用新时区。

API 余额不足、限流、超时、Key 不被接受或模型无权限时，界面保留固定原因；允许
ARL 备用时，在剩余时间内尝试一次 ARL，否则返回本地功能或要求明确输入。遇到云端
错误会暂停后续尝试，避免反复请求。可“重新允许 API 尝试”，这只解除暂停，不清空用量。
本地设备动作不会因为 API 错误而被重新执行，也不会在结果未知时盲目重放。

## 各接口改善什么

| 能力 | Friday 中的用途 | 结果边界 |
| --- | --- | --- |
| Responses | 家庭问题转成只读查询、语音语义和任务草稿 | 读数仍由本地真实来源给出；任务保留原有预览与确认 |
| Decisions | 旧版文字规划前的意图建议与有限类别影子判断 | 未经过任务校准不成为动作依据；不自动控制设备 |
| Realtime | 家庭对话中的主动语音输入 | 最多录 8 秒；转写插入光标处，核对后再发送 |
| Image API | 无 MV 歌曲的背景预取 | 仅发送歌名、演唱者，不发送歌曲音频、歌词或家庭画面 |

Realtime 为本机同源 WebSocket 中转，长期 Key 不发给网页。取消、离开页面、隐藏页面
或授权迟到后，会停止本轮音轨与连接；现有本地语音识别链保留。云端语音不可用时，
输入草稿与文字发送保留。语音与图片各自需要单独开启，不会随文字通道一起启用。

## KTV 自动背景

在同一设置中开启“自动为歌曲生成背景”。默认跳过已有可用 MV 的曲目；需要时可在
“模型配置”选择已有 MV 也生成。Mac 以低并发预取待唱歌曲，按歌曲资料、模型与提示
版本复用图片。先显示本地主题，图片完成后才交给当前歌曲；迟到结果不能覆盖下一首。
图片生成、下载或校验失败，都不阻止音源准备、起播、歌词和伴奏。

Mac 和 NAS 使用原有歌曲媒体票据传递经过校验的 PNG；电视不会取得 API Key 或房间
控制密钥之外的新权限。新图片进入现有 NAS/电视媒体缓存与管理范围；Mac 的独立
背景库最多保留配置的张数，达到上限后停止生成并保留本地主题，不自动删除未知文件。
已有缓存图在 API 额度不足或关闭生成后仍可使用。

CLI、桌面后端和 KTV 服务默认共用当前用户的 Friday 智能配置目录；需要隔离部署时，
给对应服务显式设置同一个 `FRIDAY_INTELLIGENCE_DIRECTORY`。该目录含私有配置、
Key、用量账本和已生成图片，不能放入可清理构建缓存或公共仓库。ARL 专有的宿主分析
契约仍走原有接口，仅在选择 ARL 或允许 ARL 备用时可用，不把 API 回执冒充原生确认。

接口依据：[Decisions](https://developers.openai.com/api/docs/guides/decisions)、
[Responses 结构化结果](https://developers.openai.com/api/docs/guides/structured-outputs)、
[Realtime](https://developers.openai.com/api/docs/guides/realtime)、
[图像生成](https://developers.openai.com/api/docs/guides/image-generation)。模型权限以自己的项目为准。

本次验证使用合成 HTTP/WebSocket、实际本地查询读数、合成 PNG 和电视端编译；
真实 API 余额、付费请求、Mac 麦克风及电视显示未因此获得现场验收。
