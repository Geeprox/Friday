# 隐私与数据流

Friday 的公开源码和合成测试不包含真实家庭配置。运行时数据、HA/MiOT 登录状态、
设备清单、米家户型/纹理、身份特征、NAS 索引、录像与模型都属于使用者的私有环境。
项目不会替你把这些材料上传到 GitHub。

- 基础控制面只绑定 loopback。启用 HA 后访问你选择的实例。米家集成本身可能访问
  小米云；局域网控制依赖上游设备与区域支持。
- 可选 Miloco、ARL 或云端模型拥有各自的数据流和收费设置。基础安装不会打开
  摄像头、麦克风或云推理；在各自 UI 审阅启用范围。
- 凭据存本机受限文件。macOS 桌面默认使用当前用户的 Application Support/Friday，
  源码运行使用忽略的 data/。HA/Xiaomi Home 的配置卷也可能含明文 token，应私密备份。
- 户型和设备坐标仅从使用者自己的导入取得。没有导入时不展示作者房型或推测方向。
- 运行诊断使用固定事件与故障码；可导出有界脱敏包。原始家庭内容、凭据、音视频和
  人物特征不应进入日志或支持工单。导出前仍应本机检查。
- 可选 LAN viewer 只接受本地明确配置的接收者和随机 key；不要把 viewer URL 分享到
  公共页面。页面录制仅限本机，音频播放不修改系统默认输出。

## 录像回看与事件证据

回看只播放本机生成的短时保护预览，保留 NAS 原片。默认整帧马赛克；显式配置本地
检测器后可选择性遮挡，异常时加强保护。播放器默认静音，视觉保护不去除原音轨中的
个人信息。取消、来源变化和过期会撤销预览；临时衍生文件仅保存在本机受限目录。
配置、限额、模型许可和验收范围见 [隐私回看](privacy-playback.md)。

事件详情复用本机已授权的历史读取，不获取新权限。来源明确记录的因果、同组记录、
时间相近和未知原因分别展示；录像只提供经核对的摄像头与时间引用。打开事件不会
自动读取视频或操作设备。ARL 通信正常、历史缓存和身份/模型能力验证也分别表达。

## 摄像头开关与暂停

米家的手动镜头开关和睡眠场景优先。Friday 后台取流、自动重连、人物识别和游戏
不会打开已关闭的镜头；旧版本保存的“自动打开摄像头”许可也不再生效。需要画面时，
先在米家打开对应镜头，Friday 才会重新接入。

在“摄像头”页或“设置 → 连接与隐私”中选择“暂停摄像头感知”，会保存暂停状态并
停止 Friday 的摄像头画面、声音输入、人物和动作识别。关闭窗口或重启 Friday 不会
取消暂停，打开游戏或预览也不能绕过它。选择“恢复摄像头感知”后，只接入米家中
已开启的镜头。此开关不改变米家自身的录像设置；要让设备镜头关闭，请使用米家的
镜头开关或睡眠场景。Friday 不强制把睡眠与关闭摄像头绑定。

镜头已开启且摄像头感知已启用时，Friday 可以默认接管。接管前会保存该镜头当时的
巡航、人物跟踪、宠物跟踪、人物特写开关及当前收藏位；接管期间暂时停用原厂跟踪，
正常停止、隐私关闭或异常退出后恢复接管前的配置，不把这些设置永久改为关闭。
镜头关闭时不转回收藏位，也不发送开启镜头的指令。

恢复使用每台摄像头的独立文件锁和持久租约。独立监护进程通过专属管道检测采集进程
退出，包括强制终止；服务重启时也先回收未完成租约，再允许接管。恢复失败会保留
原始配置并重试，只有属性读回匹配后才标记完成。断网、设备断电、主机断电或所有
恢复进程被终止时无法保证即时恢复，需等网络、设备和 Friday 恢复运行后完成回收。
这些保证针对接管时保存的配置；不会猜测旧版本已经遗失或被覆盖的历史配置。

## 发布审计

`python3 scripts/audit_publication.py` 扫描 Git 文件清单中的私有文件、个人主目录路径、
常见凭据、JWT、邮箱、硬件地址和未审阅二进制；输出文件位置，不输出命中的秘密。
维护者可提供忽略目录中的 `--private-patterns` JSON 字面量列表，额外核对自己的身份、
地址、设备与凭据。生成扫描报告放在 .artifacts/。

公开前还要对秘密扫描器、发布源码、可达 Git 历史、分支、标签、Release、issue/PR
附件和 CI 日志分别审查。当前文件被删除不等于历史被删除。私有研发历史保留在私有
仓库，公开仓库从审阅后的源码创建干净提交；不上传旧历史、工作区备份和现场截图。

自动检查不能保证发现所有个人信息。发布报告应写清实际检查范围与剩余限制，不能
用“零命中”声称任何环境、所有历史或所有硬件均已验收。
